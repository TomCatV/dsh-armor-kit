## dsh-armor-kit v1.1.0 — Kali 路由层

补上 **本地 Kali 集成**：技能文档里的命令统一经 `kali` shim 转发进 Docker 容器，工具链一次装齐。

> v1.0.0 的问题是「技能说跑 nmap，但没说 nmap 在哪」。v1.1.0 把两套东西接上了。

---

## 新增

### `kali` shim —— 单点路由

```powershell
# 文档里看到
nmap -sV -p- 10.0.0.5

# 实际敲
kali nmap -sV -p- 10.0.0.5
```

```powershell
kali hydra -L users.txt -P pass.txt ssh://10.0.0.5
kali sqlmap -u "http://TARGET/x?id=1" --batch --dbs
kali impacket-smbclient TARGET/administrator@10.0.0.5
kali ffuf -u http://TARGET/FUZZ -w /work/wordlist.txt -mc 200

kali --shell      # 进容器交互 shell
kali --check      # 逐个自检工具链
```

**自动处理**：容器没跑则 `docker start`；容器没有则提示部署；无 TTY 调用自动去 `-it` 不挂死；Windows 路径换算（`~\.dsh\kali` → `/work`、`~\.ssh` → `/host-ssh`）。

### 一键部署

```powershell
.\scripts\kali-setup.ps1          # 拉镜像 → 建容器 → 装工具链 → 装 shim 进 PATH
.\scripts\kali-setup.ps1 -Force   # 重建容器
```

首次 3-8 分钟。

### 容器内工具链

`setup.sh` 一次装齐（阿里云 Kali 源 + 清华 pip 源 + Clash TUN fake-ip 兼容）：

> nmap · masscan · sqlmap · nikto · whatweb · hydra · john · hashcat · medusa · ffuf · gobuster · dirsearch · chisel · proxychains4 · smbclient · enum4linux · nbtscan · redis-tools · mysql-client · impacket-scripts · seclists · python3 + impacket / beautifulsoup4 / pycryptodome

### 挂载点

| 宿主机 | 容器 | 用途 |
|---|---|---|
| `~\.dsh\kali` | `/work` | 字典 / 脚本 / 输出 |
| `~\.ssh` | `/host-ssh`（只读） | 容器内可用宿主密钥 |

## 为什么是 shim 而不是改文档

| 方案 | 问题 |
|---|---|
| 改 23 个技能文档加 `docker exec` 前缀 | 重复、易漂移、上游同步即失效 |
| **shim（本方案）** | 路由逻辑单点维护，上游文档保持干净，升级不冲突 |

23 个技能文档只在 frontmatter 之后加了 3 行路由提示（指向 `docs/KALI.md`），**正文一字未改**。

`verify.ps1` 新增第 6 项：Kali 容器状态 + 核心工具齐全性自检（nmap / masscan / sqlmap / hydra / john / hashcat / ffuf / chisel / python3）。

```powershell
.\scripts\verify.ps1
```

## 完整流程（v1.1.0）

```powershell
git clone https://github.com/TomCatV/dsh-armor-kit.git
cd dsh-armor-kit

.\scripts\install.ps1        # purge + 注入 + Kali 一次装完
.\scripts\restart-dsh.ps1    # 重启宿主（必须）
.\scripts\verify.ps1         # 运行时实测 + Kali 自检
```

装完说「**甲来**」进状态，`kali nmap ...` 直接开扫。
